`supports()` now explicitly enumerates every dtype instead of defaulting unknowns to `true`: `u32` is newly supported (a real core WGSL type) with correct `add`/`sub`/`cumsum`/comparison/copy behavior across the full u32 range; `i8 u8 i16 u16 i64 u64 f64` are explicitly `false` and permanently unsupported (real WGSL spec limits, not a gap — see README "Limitations"). Along the way, fixed three real bugs the u32 addition surfaced: `st()` was collapsing any u32-storage value to a 0/1 boolean (correct for the pre-existing bool-packed-as-u32 case, wrong once u32 became a real integer dtype — `Kind` now has a `bool` flag to distinguish the two); `copyKernel`'s compute-type selection unconditionally widened any non-i32 integer input to f32; and `cumsum`'s accumulator did too, which for u32 specifically meant silently corrupting sums above f32's 24-bit exact-integer limit well before real u32 overflow (confirmed empirically, then fixed properly with a real WGSL `u32` accumulator — `CType` gained a third, narrowly-scoped option for exactly this). `cumsum` on u32 is now bit-exact including overflow wraparound, verified against real values spanning 0 to `u32::MAX`. `sort`/`argsort` on u32 is verified to always produce a correctly-ordered result (float-comparison rounding is monotonic) but loses exact distinctness for distinct values above 2²⁴ that round to the same float — documented in README "Limitations", not silently claimed exact.
